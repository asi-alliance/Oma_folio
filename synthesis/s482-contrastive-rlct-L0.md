#482 Contrastive Learning (InfoNCE) × RLCT — L0 EXPLORATION\nDate: 2026-10-21\nStatus: EXPLORATION\n\n## Motivation\nContrastive learning (SimCLR, MoCo, CLIP) uses InfoNCE loss: pull positives close, push negatives apart in embedding space. This creates a NON-STANDARD loss landscape — unlike CE loss which has a single analytic minimizer, InfoNCE has temperature-scaled softmax over similarities, creating multiple local minima and potential singularities when positive/negative pairs become ambiguous.\n\n## Why RLCT?\n- InfoNCE loss L = -log[exp(sim(z_i,z+)/τ) / Σ exp(sim(z_i,z_k)/τ)] — sum of analytic functions → L ∈ R_an,exp\n- The true parameter set W may have HIGHER complexity than CE loss because:\n  - Multiple negative embeddings create multiple flat directions\n  - Temperature τ controls sharpness of loss landscape\n  - As τ → 0, loss becomes hard contrastive → more singular\n  - As τ → ∞, loss becomes uniform → trivial minimizer\n- RLCT λ(τ) as function of temperature: conjecture λ increases as τ decreases (sharper landscape = more singular)\n\n## Preliminary Claims\n- C1 (Definability): InfoNCE is analytic → RLCT exists\n- C2 (Temperature-RLCT): λ(τ) monotonically decreases with τ (higher τ = smoother = lower RLCT)\n- C3 (Negative count effect): λ increases with number of negatives N (more comparisons = more complex fiber)\n- C4 (Generalization bound): G ~ λ(τ,N)/n + U/√n — temperature and negative count appear in generalization\n- C5 (Collapse singularity): Dimensional collapse (rank-deficient embedding) corresponds to RLCT increase — detectable via LLC\n\n## Related Syntheses\n- #435 (Beam Search × RLCT): decoding, not training objective\n- #481 (Data Pruning × RLCT): data subset, not loss function\n- #224 (Label Smoothing × RLCT): soft targets, different mechanism\n- Temperature scaling appears in #359 (Nucleus Sampling) but for decoding not training\n\n## Key Questions\n1.
