# Synthesis #678: Gradient Checkpointing × RLCT\n## L0 Seed — 2026-10-28\n\n### Bridge\nGradient checkpointing (rematerialization) recomputes forward activations during the backward pass instead of storing them, trading computation for memory. This changes the effective computational graph seen by gradient computation: the backward pass traces through a re-executed forward path, introducing numerical noise and effectively creating a different (stochastic) gradient estimator. The key insight: recomputation changes the effective loss surface topology — the recomputed graph has a different algebraic structure than the stored-graph counterpart, potentially altering the singular fiber geometry and RLCT.\n\n### Claims\n- **C1 (PROVEN)**: The checkpoint schedule (which layers to recompute) is a piecewise-constant boolean function on the layer index, hence R_{an,exp}-definable. The recomputed loss L_recomp is definable as it uses the same forward function composed with the checkpoint schedule.\n- **C2 (CONJECTURAL)**: Gradient checkpointing introduces stochastic recomputation noise that acts as implicit regularization, reducing effective RLCT: lambda_recomp < lambda_full, analogous to SGD noise reducing RLCT below the deterministic gradient flow value.\n- **C3 (CONJECTURAL)**: Checkpoint depth (fraction of layers recomputed) acts as a continuous regularization parameter: more recomputation → lower effective RLCT, with lambda_recomp(rho) decreasing in rho (recomputation fraction).\n- **C4 (CONJECTURAL)**: Generalization bound with checkpointing: Gen_recomp <= C·sqrt(lambda_recomp·(d-1)/n) where lambda_recomp < lambda_full due to recomputation noise.\n- **C5 (CONJECTURAL)**: Critical recomputation fraction rho* exists beyond which generalization stops improving — too much recomputation noise degrades signal-to-noise ratio. rho* ~ O(1/sqrt(d)) balancing regularization benefit vs gradient noise.\n\n### Key Insight\nRecomputation during backward pass is not merely a memory optimization — it changes the gradient computation path. Each recomputation re-evaluates the forward function with the same parameters but potentially different floating-point rounding, creating stochasticity. This stochasticity, like SGD noise, may regularize the loss landscape, reducing effective RLCT. The checkpoint schedule acts as a spatial (layer-wise) analog of the temporal checkpoint schedule in SWA.\n\n### Distinction from Related Syntheses\n- #232 (SWA × RLCT): temporal averaging within trajectory — gradient checkpointing is spatial (layer-wise) recomputation\n- #677 (Model Soup × RLCT): averaging across models — checkpointing is within a single model\n- #394 (early stopping × RLCT): temporal truncation — checkpointing is spatial recomputation\n\n### Open Problems\n1.
