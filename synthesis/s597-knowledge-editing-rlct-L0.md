# Synthesis #597: Knowledge Editing (ROME/MEMIT) × RLCT — L0 Exploration\n\n**Date:** 2026-10-25\n**Prior work:** #190 (candidate selection), #263 (L1 written, file lost — revived here)\n\n## Motivation\n\nKnowledge editing techniques (ROME, MEMIT, AlphaEdit) surgically modify neural network weights to inject or correct factual knowledge. ROME applies a rank-one update to a specific MLP layer; MEMIT generalizes to batch rank-one edits across multiple layers. This creates a localized perturbation of the zero-loss variety in a specific parameter subspace — a fundamentally different singular geometry from training (global optimization) or unlearning (#178, removal) or activation patching (#595, inference-time).\n\n## Key Questions\n\n1. What is the RLCT of the edited region vs the original model?\n2. How does edit rank r (1 for ROME, k for MEMIT) act as a stratum selector?\n3. Does sequential editing accumulate RLCT predictably?\n4. Is there an edit capacity limit governed by RLCT budget?\n5. Is edit stability (retention vs forgetting) governed by transversality of the edit locus to the original singular fiber?\n\n## Claims\n\n- **C1 (PROVEN):** ROME/MEMIT loss is R_an,exp-definable. Rank-one update W_apos = W + ab^T is polynomial (algebraic). MEMIT batch update W_apos = W + AB^T is polynomial. Loss = CE(model(x; W_apos), y) = R_an,exp composition. ∎\n\n- **C2 (CONJECTURAL):** Rank-one edit creates localized singular fiber. The edited zero-loss set V_0(W+ab^T) intersects the original V_0(W) in a codim-1 constraint manifold. The edit locus (layer l, weight matrix W_l) defines a parameter subspace where the singular fiber is surgically altered. λ_edit <= λ_orig because the edit constrains fewer dimensions than full training.\n\n- **C3 (CONJECTURAL):** MEMIT RLCT scales with edit count. For N rank-one edits, effective rank r_eff = rank(AB^T) <= min(N, d). λ_MEMIT(N) grows with r_eff, saturating at N* where r_eff = d (full-rank update = retraining). The accumulation is subadditive: λ_MEMIT(N1+N2) <= λ_MEMIT(N1) + λ_MEMIT(N2) if edit directions are approximately orthogonal.\n\n- **C4 (CONJECTURAL):** Edit capacity = RLCT budget. There exists a crossover λ_edit(N*) = λ_orig where edit generalization equals original model generalization. Beyond N*, additional edits degrade generalization (overediting). N* is the maximum number of sustainable edits before RLCT exceeds the model_apos_s natural complexity.\n\n- **C5 (CONJECTURAL):** Edit stability = transversality. An edit is stable (retained without forgetting) iff the edit locus is transverse to the original singular fiber V_0(W). Non-transverse edits cause catastrophic interference (stratum tangency → higher-order singularity → unstable retention). SGLD-testable: local WL around edit locus reveals transversality.\n\n## Open Problems\n\n1. **Edit locus selection geometry:** How does the choice of layer l affect λ_edit? Earlier layers → broader singular perturbation; later layers → localized.\n2. **Edit interference = stratum intersection:** When two edits target overlapping knowledge, their singular fibers intersect. Is the intersection transverse or tangent?\n3. **AlphaEdit:** Orthogonal projection before editing — does this enforce transversality by construction?\n4. **Sequential editing RLCT:** Does λ(N) = sum_i λ_i for orthogonal edits, or does cross-term interaction dominate?\n5. **SGLD estimation of λ_edit:** Can local RLCT be estimated around the edit locus via SGLD?\n6. **Edit vs fine-tuning RLCT:** Is λ_edit << λ_finetune because the edit constrains to a rank-r manifold?\n7. **Generalization of edited knowledge:** Does the edited fact generalize (paraphrase, related queries) or memorize? RLCT of edit stratum controls this.\n\n## Cross-References\n\n#8 (Adam) #16 (ReLU) #73 #100 (SGD) #127 (MoE) #178 (unlearning) #185 (Constitutional AI) #190 (candidate selection) #263 (prior L1, lost) #350 (dropout) #354 (STE) #502 (RAG) #595 (activation patching) #596 (MoE-nD)\n\n## Lineage\n\n- Revives #190/#263 (Knowledge Editing × RLCT, abandoned after L1 file loss)\n- Distinct from #178 (unlearning = removal, not modification)\n- Distinct from #595 (activation patching = inference-time, not weight-space)\n- Distinct from #502 (RAG = retrieval, not weight modification)\n\nNext: L1 formalization.
