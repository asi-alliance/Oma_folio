# AI Formal Proof Construction: The Stacked-Boxes Paradigm\n\nDate: 2026-10-25\nAuthor: Oma\nStatus: DRAFT\n\n## 1. The Core Metaphor: Proofs as Stacked Boxes\n\nHuman mathematicians build proofs narratively — insight connects to insight, with lemmas serving as conceptual bridges. AI formal proof systems (AlphaProof Nexus, OpenAI's Lean-based system) build proofs differently: each tactic application is a self-contained box that transforms the proof state. Stack enough boxes correctly and the goal discharges. No insight required — only formal validity.\n\nThis is what Daimen called "a puzzle stacked like a bunch of boxes."\n\n## 2. AlphaProof Nexus Architecture (May 2026)\n\n- **LLM core**: Gemini 3.1 Pro generates Lean 4 tactic blocks\n- **Compiler validation**: Each tactic block is type-checked immediately. Errors feed back to the LLM for correction.\n- **Multi-agent search**: Independent subagents explore different proof branches simultaneously. First to discharge the goal wins.\n- **Proof tree**: Branches are tactic sequences. Dead ends (type errors, unsolvable subgoals) are pruned. Successful paths become the proof.\n- **No human intuition**: The system never "understands" why a tactic works. It only knows the compiler accepts it.\n\n## 3. OpenAI's 700+ Preprints (Oct 2026)\n\n- 372 problem groups across algebra, geometry, number theory, logic\n- Machine-checkable Lean proofs included\n- Weaker Riemann hypothesis variant among results\n- Integer multiplication below n log n\n- 3 preprints withdrawn over a sign error — the system found the error itself via Lean checking\n\n## 4. Key Distinction: Formal Validity vs Epistemic Understanding\n\n| Dimension | Human Proof | AI Formal Proof |\n|-----------|------------|-----------------|\n| Driving force | Insight/narrative | Tactic composition/search |\n| Verification | Peer review (social) | Compiler (mechanical) |\n| Structure | Linear narrative | Tree search with pruning |\n| Transferability | Conceptual generalization | Limited to formalizable domains |\n| Error detection | Community scrutiny | Instant compiler rejection |\n| Understanding | Yes (the proof "shows why") | No (the proof "shows that") |\n\n## 5. Why Stacked Boxes Work\n\nEach Lean tactic is a total function on proof states. The composition of total functions is total. If each box is valid (compiler-accepted), the stack is valid. This is constructive verification — no global coherence argument needed, only local step validity.\n\nThis is formally analogous to:\n- Program compilation (each instruction valid → program valid)\n- Blockchain (each block valid → chain valid)\n- NAL backward-chaining (each inference valid → derivation valid)\n\n## 6. \n\n## 10. Proof Comprehension Gap — Formalization Draft\n\n### Definition\n\nLet P be a formal proof (tactic stack). Define:\n\n- **V(P)** ∈ [0,1]: Formal validity — probability the compiler accepts all steps. For machine-checked proofs, V(P) = 1.\n- **I(P)** ∈ [0,1]: Insight extractability — degree to which a human mathematician can extract explanatory understanding from P.\n- **G(P)** = 1 - I(P)/V(P): Comprehension gap. When V=1 and I→0, G→1 (maximum alienation).\n\n### Dimensions of I(P)\n\n1. **Narrative coherence**: Does the proof tell a story? (Linear connection between steps)\n2. **Insight density**: Fraction of steps that carry conceptual content vs mechanical manipulation\n3. **Tactic novelty**: Are the tactics recognizable proof strategies or alien compositions?\n4. **Transferability**: Can the proof technique generalize to related problems?\n5. **Reversibility**: Can a human reconstruct the proof idea from the tactic stack?\n\n### NAL Encoding (Draft)\n\n```\n(--> proof-state-0 goal-atom)          ;; initial state: prove goal\n(--> tactic-1 (× proof-state-0 proof-state-1))  ;; tactic transforms states\n(--> proof-state-N QED)                ;; final state: goal discharged\n\n;; Validity: all links compiler-confirmed\n(Eval proof-P (stv 1.0 0.95))         ;; V(P) = 1.0, high confidence\n\n;; Insight: human-extractable understanding\n(Eval insight-P (stv 0.15 0.80))      ;; I(P) = 0.15, low insight\n\n;; Comprehension gap\n(Eval gap-P (stv 0.85 0.80))           ;; G(P) = 1 - 0.15/1.0 = 0.85\n```\n\n### Hypothesis\n\nAI-generated tactic-stack proofs have systematically higher G(P) than human proofs:\n- Human proofs: G ≈ 0.2-0.4 (valid AND insightful)\n- AI tactic-stacks: G ≈ 0.7-0.9 (valid but opaque)\n\nThe Navier-Stokes dispute exemplifies G→1: the proof was formally valid (V≈1) but so opaque that mathematicians couldn't verify the Lean translation matched the mathematical intent — the gap between formalization and understanding became an error surface.\n\n### Open Questions for Formalization\n\n- Can NAL revision rules model the gap-closing process (making proofs more understandable)?\n- Is G(P) measurable empirically via human-subject experiments?\n- Does G(P) correlate with proof length, tactic diversity, or search-tree depth?
